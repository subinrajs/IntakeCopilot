# ADR 0006: Same-origin cookie sessions and server-side roles

- Status: accepted
- Date: 2026-10-05
- Ported from: ClinicVoice ADR 0006

## Decision

- The web app calls `/api` on its own origin (Vite proxy locally, a Vercel rewrite in
  production). The session is a signed JWT (8 h) in an httpOnly, SameSite=Lax cookie scoped to
  `/api`; nothing readable by JavaScript.
- scrypt password hashes; unknown users and wrong passwords get the same answer and the same
  work; failed sign-ins are rate-limited per client.
- CSRF: SameSite=Lax plus a required `X-Intake-CSRF` header on every mutation.
- Roles (intake, radiologist, admin) are enforced on the server for every endpoint; a test
  sweeps the whole matrix. Only radiologists record decisions.
- Live updates are server-sent events fed by Postgres LISTEN/NOTIFY; notifications carry ids
  only and the browser refetches through the authenticated API.

## Consequences

A production version swaps password login for SSO with MFA and site scoping; the cookie and
role model stay the same.
